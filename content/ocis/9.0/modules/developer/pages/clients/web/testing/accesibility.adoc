== Introduction

Accessibility is a crucial aspect of web development. It ensures that web applications are usable by everyone, including people with disabilities.

== What Tools We Use

=== eslint-plugin-vuejs-accessibility

We use link:https://github.com/vue-a11y/eslint-plugin-vuejs-accessibility[eslint-plugin-vuejs-accessibility] to quickly catch accessibility issues in the codebase. This plugin is used in the link:https://www.npmjs.com/package/@ownclouders/eslint-config[@ownclouders/eslint-config].

=== @axe-core/playwright

We use link:https://github.com/dequelabs/axe-core-npm[@axe-core/playwright] to automatically test the accessibility of the ownCloud Web client. All tests are run automatically on every pull request (and on manual runs of the workflow). Pull requests that only change documentation skip them. We are not running dedicated accessibility tests and instead make them part of the E2E tests. This way we do not have to maintain duplicate tests and we can granularly add accessibility tests to the specific steps of the tests. The tests are considered failed if any `serious` or `critical` accessibility violations are found.

==== Running Accessibility Tests

To run the accessibility tests, you can simply run our existing E2E tests using the following command:

[source,bash]
----
pnpm test:e2e:playwright
----

==== Skipping Accessibility Tests Locally

If you want to skip the accessibility tests, you can add the `SKIP_A11Y_TESTS` environment variable to your command.

[source,bash]
----
SKIP_A11Y_TESTS=true pnpm test:e2e:playwright
----

WARNING: In the current code, this check is inverted: the accessibility tests are only skipped with `SKIP_A11Y_TESTS=false`, see `skipA11y` in `tests/e2e/config.js`. This is tracked as a bug.

==== Accessibility Report

After the tests are run, a JSON accessibility report is generated in the `reports/e2e/a11y-report.json` file. This report contains detailed information about the accessibility violations found in the tests.
