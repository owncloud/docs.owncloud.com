== Beta Testing

This document is supposed to give you some ideas how and what to test on ocis. It's not meant to be an extensive list of all tests to be done, rather it should help you, as beta-tester, to get started and enable you to get creative and create your own test-cases. link:https://twitter.com/sempf/status/514473420277694465[Derive from these examples, be creative, do unusual and unconventional things, to try to break things].

One option to create new test-cases and to stress the system is to examine what the
xref:ocis/development/testing.adoc[API acceptance-tests] or the xref:#web[web-UI] does, xref:#decode_https_traffic_with_wireshark[examine the requests] and do something a bit different with curl. This is also a good way to find out how APIs work that are not already fully documented.

Some cases have suggested setup steps, but feel free to use other setups. This can include:

* different deployment methods

* different identity managers (e.g. xref:ocis/deployment/ocis_ldap.adoc[different external LDAP], internal IDM)

* different reverse proxies

* different OpenIDConnect IDPs (e.g builtin IDP, xref:ocis/deployment/ocis_keycloak.adoc[keycloak], AzureAD)
** for some functionalities you will need an xref:ocis/deployment/ocis_ldap.adoc[LDAP server] where the IDP and oCIS both get the users from the:
** xref:ocis/deployment/ocis_keycloak.adoc[keycloak example]
** xref:{dev-s-path}/idp/index.adoc[service configuration]

* different storage systems (decomposedFS on local POSIX (default), xref:ocis/storage-backends/dcfsnfs.adoc[decomposedFS on NFS],
xref:ocis/deployment/ocis_full.adoc[S3])

It's a good idea to test ocis in the same environment where you are planning to use it later (with the LDAP server, storage system, etc. of your organisation).

== Run oCIS

For a quick start, please have a look into the xref:ocis/development/getting-started.adoc[getting started documentation of oCIS]. If you would like to access oCIS remotely please refer to the xref:ocis/deployment/basic-remote-setup.adoc[Basic Remote Setup] section.

=== Additional Tips

* To allow basic auth (e.g. to easily access oCIS using curl commands) you have to set `PROXY_ENABLE_BASIC_AUTH=true` environment variable
* If you cannot use real SSL Certificates set `OCIS_INSECURE=true` as environment variable

== Spaces

Prerequisite:

* Start ocis with basic auth
* Variable declaration, for curl examples: +
[source,bash]
----
SERVER_URI=https://localhost:9200
GRAPH_API_PATH=graph/v1.0
SHARE_API_PATH=ocs/v2.php/apps/files_sharing/api/v1/shares
USER=admin
PASSWORD=admin
----

* Create a new user +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$GRAPH_API_PATH/users" -X POST -d'{"displayName":"Example User","mail":"example@example.org","onPremisesSamAccountName":"example","passwordProfile":{"password":"ThePassword"}}'
----

* Give the user the "Space Admin" role:
.. get the id of the user: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/users/<user-name> | jq '.id'
----

.. Assign role user to role: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/api/v0/settings/assignments-add -d'{"account_uuid":"<user-id>","role_id":"2aadd357-682c-406b-8874-293091995fdd"}
----

* Create a space: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$GRAPH_API_PATH/drives" -X POST -d'{"Name":"Space for finance","driveType":"project", "description":"we need some space"}'
----

* List spaces: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/me/drives
----

* Disable a space: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X DELETE
----

* Delete a space: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X DELETE -H'Purge: T'
----

* Restore a space: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X PATCH -d"{}" -H"Restore: true"
----

* Rename the space: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X PATCH -d'{"name":"नेपालि नाम"}'
----

* Change description of the space: +
 +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X PATCH -d'{"description":"this contains important data"}'
----

* Change quota of the space +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X PATCH -d'{"quota":{"total":<bytes>}}'
----

* Change image of space:
.. upload an image file to the `.spaces` folder: +
[source,bash]
----
curl -k -u $USER:$PASSWORD https://localhost:9200/dav/spaces/<space-id>/.space/<file-name> -T <path-of-local-image> -v
----

.. Note the id provided in the `Oc-Fileid` header
.. set the image as "special-folder": +
[source,bash]
----
curl -k -u $USER:$PASSWORD  $SERVER_URI/$GRAPH_API_PATH/drives/<space-id> -X PATCH -d'{"special":[{"specialFolder":{"name":"image"},"id":"<oc-fileid>"}]}'
----

* Share a space: +
[source,bash]
----
curl -k -u $USER:$PASSWORD $SERVER_URI/$SHARE_API_PATH  -d'space_ref=<space-id>&shareType=7&shareWith=<receiver-username>&role=<role>'
----

** Roles:
*** viewer
*** editor
*** manager

* Share a resource within a space +
[source,bash]
----
curl -k -u $USER:$PASSWORD $SERVER_URI/$SHARE_API_PATH -d'shareType=0&shareWith=<receiver-username>&space_ref=<space-id>%2F<resource>&permissions=<permissions>
----

** Possible permissions
*** 1 = read
*** 2 = update
*** 4 = create
*** 8 = delete
*** 15 = read/write
*** 16 = share
*** 31 = All permissions

* WebDAV
** root: `\https://<server-uri>/dav/spaces/<space-id>`
** xref:#webdav[example commands for operations]

== Tips for Testing

=== WebDAV

WebDav is accessible under different path

* Old: +
`\https://\<ocis-server\>/remote.php/webdav`
* New: +
`\https://\<ocis-server\>/remote.php/dav/files/\<username\>`
* Spaces:` +
\https://\<ocis-server\>/dav/spaces/\<space-id\>`

WebDav specifications can be found on http://webdav.org/

Here some general WebDav request examples:

variable declaration:

[source,bash]
----
SERVER_URI=https://localhost:9200
API_PATH=remote.php/webdav
USER=admin
PASSWORD=admin
----

* List content of root folder:  +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$API_PATH/" -X PROPFIND
----

* List content of sub-folder: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$API_PATH/f1" -X PROPFIND
----

* Create a folder: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$API_PATH/folder" -X MKCOL
----

* Delete a resource: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$API_PATH/folder" -X DELETE
----

* Rename / move a resource: +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$API_PATH/folder" -X MOVE -H "Destination: $SERVER_URI/$API_PATH/renamed"
----

* Copy a resource:
 +
[source,bash]
----
curl -k -u $USER:$PASSWORD  "$SERVER_URI/$API_PATH/folder" -X COPY -H "Destination: $SERVER_URI/$API_PATH/folder-copy"
----

== Decode HTTPS Traffic with Wireshark

To decode the HTTPS traffic we need the keys that were used to encrypt the traffic. Those keys are kept secret by the clients, but we can request the clients to save them in a specific file, so that wireshark can use them to decrypt the traffic again.

. Create key file: `touch /tmp/sslkey.log`
. Start wireshark
. Set log filename
** Navigate to Edit=>Preferences=>Protocols=>TLS
** In the field `(Pre)-Master-Secret log filename` enter `/tmp/sslkey.log`

. Decode as HTTP
** Navigate to Analyze=>Decode As...
** Click the + button
** Set Field: `TLS Port; Value=9200; Type: Integer, base 10; Default (none); Current HTTP` (adjust the port if you are using another one than 9200)

. Start recording
** use `port 9200` as capture filter to only record ocis packages
** use `http` as display filter to see only decoded traffic

. Run test-software with `SSLKEYLOGFILE=/tmp/sslkey.log` as env. variable e.g.
** run command  +
[source,bash]
----
curl: `SSLKEYLOGFILE=/tmp/sslkey.log curl -k -u admin:admin https://localhost:9200/ocs/v1.php/cloud/users
----

** Browser: `SSLKEYLOGFILE=/tmp/sslkey.log firefox`
** LibreOffice: `SSLKEYLOGFILE=/tmp/sslkey.log libreoffice`
** Acceptance tests: `SSLKEYLOGFILE=/tmp/sslkey.log make test-acceptance-api ...`

== Format Output

* Piping _xml_ results to `xmllint` gives you nice formats. E.g. +
[source,bash]
----
curl -k --user marie:radioactivity "https://localhost:9200/ocs/v1.php/apps/files_sharing/api/v1/shares" | xmllint --format -*
----

* Piping _json_ results to `jq` gives you nice formats. E.g. +
[source,bash]
----
curl -k --user marie:radioactivity "https://localhost:9200/ocs/v1.php/apps/files_sharing/api/v1/shares?format=json" | jq
----
