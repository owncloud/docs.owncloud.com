== Request Flow

The following sequence diagram describes the general request flow. It shows where authentication, user lookup and token minting are happening:

[mermaid, width=600]
----
sequenceDiagram
    autonumber
    participant C as Client (Web / Desktop / Mobile)
    participant P as proxy (:9200)
    participant A as auth-bearer + idp
    participant GR as graph (:9120)
    participant D as ocdav (:9163)
    participant G as gateway (:9142)
    participant S as storage-users (:9157, driver ocis)

    C->>P: HTTPS WebDAV request (/dav/...) with bearer token
    P->>A: validate bearer token (userinfo)
    A-->>P: authenticated user (sub, iss)
    P->>GR: look up user via CS3 userprovider
    GR-->>P: user (UUID, username)
    Note over P: mint x-access-token with user UUID and username
    P->>D: forward request to ocdav
    D->>G: CS3 request (Stat / List / Read)
    G->>S: CS3 storage call
    S-->>G: CS3 response
    G-->>D: CS3 response
    D-->>P: WebDAV response
    P-->>C: HTTPS response
----

NOTE: This diagram reflects oCIS 9.0. Earlier versions used an `accounts` service for user lookup and provisioning, which has been removed. User management is now provided by the `graph`, `idm` and `idp` services.
